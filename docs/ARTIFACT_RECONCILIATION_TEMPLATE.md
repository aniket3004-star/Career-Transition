# V1 Artifact Reconciliation Template

Date: 2026-09-19

## Purpose

Use this record to reconcile the project ZIP artifacts against one another without treating filenames, stated defaults, or self-generated fixtures as proof of correctness. This document is an intake/evidence template; it does not claim that any uninspected archive has been reviewed or tested.

## Evidence handling rules

1. Preserve each original ZIP unchanged.
2. Record the exact filename, byte size, and SHA-256 of the archive before extraction.
3. Extract each archive into a separate, version-labelled directory; never overlay versions.
4. Record internal paths, package/version markers, entry points, dependencies, and stated assumptions.
5. Distinguish `observed in files`, `executed`, `independently verified`, and `not checked`.
6. Treat a test as self-consistency when expected values were generated by the same implementation or conventions under test.
7. Do not mark a subsystem validated without independent evidence, reproducible commands, and retained outputs.

## V1 evidence labels

- **FILE-OBSERVED:** directly visible in archive/repository contents.
- **EXECUTED-SELF-CONSISTENCY:** executed, but test oracle shares implementation or conventions.
- **EXECUTED-INDEPENDENT:** executed against independently sourced expected values.
- **NOT-RUN:** no execution evidence.
- **BLOCKED:** cannot proceed without missing inputs, access, or prerequisite validation.
- **INCONCLUSIVE:** evidence does not settle the claim.

## Exit criteria for Gate 1

- All known archives have exact identity and hashes.
- Internal contents and versions are inventoried without cross-version overwrites.
- Harness v29–v33 and relevant validator/rules packages are compared at file and behavior level.
- Duplicate/superseded/incompatible artifacts are identified with evidence.
- Canonical choices are explicitly provisional or approved, with rationale and remaining tests.
- No unexecuted or self-consistency-only test is represented as independent validation.
